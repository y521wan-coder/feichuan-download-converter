# 抖音单条图文图片和音频下载调研

日期：2026-08-14（北京时间）

## 一手项目核对

- `jiji262/douyin-downloader`：https://github.com/jiji262/douyin-downloader
  项目主分支 README 明确支持 `/note/{note_id}`、`/gallery/{note_id}` 单图文、短链解析和音乐
  下载；仓库声明 MIT。其行为证明“单条图文同时处理图集与音乐”是可行流程。
- 本项目已有 `DouyinEnumerator._parse_aweme` 会从 `image_post_info.images`/`images` 读取作品
  图片，并优先 `origin_image`，随后选择 `display_image` 等候选；已有下载器负责 WebP 校验、
  转换、`.part` 与整组暂存后提交。因此不需要引入或复制第三方实现。

## 采用与拒绝

- 采用：只参考“单图文按作品详情区分图集与背景音乐”的字段和流程；单条详情由现有浏览器会话
  捕获，继续复用本项目解析器、命名器、下载器和安全边界。
- 采用：图片作为一个原子组件下载，音频继续走现有单链接 yt-dlp/浏览器兜底；两组件独立记录
  成败，以支持部分成功。
- 拒绝：抓取页面所有 `<img>`，避免头像、二维码、封面、推荐内容和界面图标混入作品图片。
- 拒绝：复制第三方代码、配置、Cookie 持久化、数据库、REST 服务或新增依赖；它们超出本功能
  范围，并会扩大许可证、隐私和维护面。

## 真实作品兼容性结论

- 真实页面已确认是 `/note/` 图文作品，并提供一张 2160×2880 的作品图片和独立背景音频。
- 当前页面未再触发旧的作品详情 XHR，但页面自身的 RSC 数据流 `window.__pace_f` 在
  `aweme.detail.images` 中提供当前作品的图片数组。因此保留旧详情接口捕获作为首选，并增加
  RSC 数据流兜底；兜底必须精确匹配短链解析后的作品 ID，不能扫描页面全部图片。
- 图片候选优先使用作品详情中的 `downloadUrlList`，再回退 `urlList`，继续交给既有 WebP 校验、
  临时文件和原子提交管线。作品数据和候选地址只在 worker 内存中使用，不进入协议、日志或磁盘。
- 图文背景音频显式使用 `bestaudio/best`，不再根据图文页面网址扩展名猜测媒体类型。
- 该修复没有复制第三方代码、增加依赖或改变许可证边界。
