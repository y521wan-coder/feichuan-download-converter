## 本轮 GitHub 查询结论

没有发现可在不引入复杂 UI、焦点风险或许可证不确定性的前提下，直接替代本项目 WinForms 无障碍交互层的活跃实现。因此自行实现标准 WinForms 界面；媒体进程层采用 FFMpegCore，云端采用腾讯官方 SDK，并用本项目接口隔离。

## 2026-08-10：WinForms 与 Python worker 协议

| 项目/资料 | 地址与活跃度/许可证 | 适配风险 | 结论 |
| --- | --- | --- | --- |
| Microsoft StreamJsonRpc | https://github.com/microsoft/vs-streamjsonrpc；核验时约 4,711 次提交、MIT | 提供完整 JSON-RPC、代理、事件、取消与多种 framing；本计划固定的是小型版本化 JSON Lines 消息，不需要远程方法代理。引入它还会要求 Python 侧匹配 JSON-RPC/framing，增加 worker 打包依赖与协议面 | 不引入；只参考其请求关联与取消思路，代码不复制 |
| .NET Process 标准流 | https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.standardoutput?view=net-10.0 | 官方明确提示同时同步读取 stdout/stderr 可能死锁；重定向要求 `UseShellExecute=false` | 采用 BCL，stdout/stderr 两个独立异步读取循环 |
| Python `json` 标准库 | https://docs.python.org/3/library/json.html | 官方指出 JSON 本身不是 framed protocol，多次连续 dump 会产生无效流；还提示限制不受信输入大小 | 采用“一行一个完整 JSON 对象”并限制单行字节数，每次写入后 flush |

实现边界：协议层不引入新 NuGet/Python 依赖；自有代码仅负责消息验证、版本握手、请求 ID、
安全字段过滤、异步管道与 worker 生命周期。下载算法仍直接复用飞船协调器。
